# Examples and evaluations

Real wrappers that `mcpgen` generated, and the harness that produced them, live on the
[`eval`](https://github.com/svd/mcp-client-kit/tree/eval) branch of this repository.

If you want to read generated code before installing anything, start at
[`eval/`](https://github.com/svd/mcp-client-kit/tree/eval/eval).

## What's on the `eval` branch

A separate project, `mcp-client-kit-eval`, with its own `pyproject.toml`, tests, and CLI
(`eval-kit`). It consumes `mcp-client-kit` as a local editable dependency and drives the
`generate-mcp-wrappers` skill against live MCP servers, committing whatever comes out.

Its own [`README.md`](https://github.com/svd/mcp-client-kit/blob/eval/README.md) covers
running the harness yourself.

[`time`](https://github.com/svd/mcp-client-kit/tree/eval/eval/time)

Each holds five files:

| File | What it is |
|---|---|
| `<server>.py` | the generated wrapper module — one `async def` per tool |
| `<server>.shapes.json` | the shape-spec sidecar that turned probed responses into typed returns |
| `<server>.verify.json` | verifier output for that run |
| `run.py` | a transport-aware sample runner |
| `session-overview.md` | narrative of how the skill executed, with run metadata |

Reading `<server>.py` next to its `<server>.shapes.json` is the fastest way to see how a
probe becomes a return type. `github` is the largest example and the one exercising the most
of the lifecycle; `time` is the smallest complete one.

## Evaluation results

[`doc/EVAL_REPORT.md`](https://github.com/svd/mcp-client-kit/blob/eval/doc/EVAL_REPORT.md) —
the aggregate matrix, per server. It is generated by `eval-kit report` and regenerates on
every run, so it is the source of truth for coverage and this page quotes no numbers from it.

## How the branch relates to `main`

`eval` is an orphan branch: it shares no history with `main` and is never merged into it.
The two are separate projects that happen to live in one repository.

`main`'s `.gitignore` excludes `eval/`, so these artifacts cannot be committed here — which
is why the links above are absolute URLs rather than relative paths. Relative links in
GitHub markdown resolve within the branch you are reading.
