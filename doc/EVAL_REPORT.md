## Known issues

Input schemas misdeclare types and requiredness: `-32602` on `openzeppelin-solidity.decimals`
(number vs string), `firecrawl.sources` taking objects rather than strings, `semgrep_findings`
rejecting an omitted `repos`. Every discriminator that mattered — `github`'s `method`/`detail`,
`notion.query_type`, `semgrep.issue_type`, `aws-knowledge.resource_type` — came from the
description sweep; the shared-param advisory surfaced only pagination, identity and template
params. Two modelling ceilings recur: array-valued discriminators cannot become overloads and
collapse to `total=False` unions (`aws-knowledge.topics`, `linear.fields`,
`firecrawl_scrape`/`_search`), and polymorphism keyed on a *response* field leaves honest `dict`
fallbacks (`stackoverflow.get_content.Data`, `notion.data.mode`), as do objects one nest deeper
(`time.ConvertedTime`, `firecrawl.metadata`). Separately, `astro-docs` saw a cached HTTP session
return another server's tool list — silent, and enough to type a wrapper against the wrong server.
